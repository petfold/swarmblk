# Phase 1 gate — 26 October 2026

The gate (ROADMAP, Phase 1): roots match Bee's pipeline for the same bytes, and a restore on a second host is byte-identical (SPEC §14, I1 and I7). A real guest changed a disk restored from Swarm, the change was checkpointed on laptop A, and laptop B restored it through its own Bee node.

## Setup

- **Node A:** Bee 2.8.3 light node under Swarm Desktop, on the machine that runs QEMU 8.2.2 with KVM. It stamps with the test batch `c7af5dda…` (immutable, depth 21).
- **Node B:** Bee 2.8.3 light node on a second laptop (Ubuntu 26.04, x86-64) on the same Wi-Fi. Its API listens on localhost only; A reaches B by SSH with a key. B has no batch and never held any of the data before the run.
- **swarmblk:** built from `c1581cb` with `swarmblk diff` added (the next commit), as one static binary (`CGO_ENABLED=0`, sha256 `d2323a54…`), copied to B.
- **Guest:** CirrOS 0.6.3 x86-64 (download checked against `SHA256SUMS`) as a raw image resized to 128 MiB; 512 MiB of RAM, 2 vCPUs. A NoCloud seed runs a script that writes `/root/gate.txt`, writes and deletes a 4 MiB file, runs `fstrim`, and powers off. CirrOS reads NoCloud meta-data only as JSON.

## Observations

1. **The gate is met.** The import's root equals Bee's for the same bytes (and the unit tests check every tree function against Bee's pipeline), and laptop B's export and QEMU's read through node B are byte-identical to the disk the guest saw.
2. **Discards keep snapshots thin.** With `discard=unmap,detect-zeroes=unmap`, `fstrim` in the guest turns free space into zero clusters of the qcow2 overlay, and the checkpoint maps them to Z_0. Most of it was zeros in the base already and uploaded nothing.
3. **Export fetched about 84 chunks/s** through one light node with 32 requests in flight: about 12,080 chunks (11,822 distinct data blocks, the tree and the manifest) in 144 s. Phase 0 measured about 170 chunks/s with many more in flight.
4. **Upload and sync dominate a checkpoint.** Rehashing 88 MiB of overlay took 9 s; sending 6,449 chunks took 29 s, and the tag reported them synced 40 s later.

## Commands

On B, once: an SSH server, Bee running with its API on localhost, and A's key installed (`ssh-copy-id -i ~/.ssh/id_ed25519.pub test@192.168.1.225` on A).

On A:

```sh
G=~/swarmblk-gate; mkdir -p $G; cd $G
export SWARMBLK_HOME=$G/home-a SWARMBLK_BATCH=c7af5ddacf81eaa13304ea78b497c8d719b2f5c0bf53b8ab01654cb4c65edecb
(cd ~/projects/swarmblk && CGO_ENABLED=0 go build -trimpath -o $G/swarmblk ./cmd/swarmblk)

wget https://download.cirros-cloud.net/0.6.3/cirros-0.6.3-x86_64-disk.img https://download.cirros-cloud.net/0.6.3/SHA256SUMS
grep ' cirros-0.6.3-x86_64-disk.img$' SHA256SUMS | sha256sum -c -
qemu-img convert -f qcow2 -O raw cirros-0.6.3-x86_64-disk.img cirros.raw
qemu-img resize -f raw cirros.raw 128M

cat > user-data <<'EOF'
#!/bin/sh
echo "swarmblk gate: $(date -u +%FT%TZ)" > /root/gate.txt
dd if=/dev/urandom of=/root/junk bs=1M count=4 2>/dev/null
sync
rm /root/junk
sync
fstrim -v /
echo "GATE MARKER: $(cat /root/gate.txt)"
poweroff
EOF
echo '{"instance-id": "swarmblk-gate", "local-hostname": "gate"}' > meta-data
cloud-localds seed.img user-data meta-data

S0=$(./swarmblk import cirros.raw)
./swarmblk restore $S0 vm.qcow2
qemu-system-x86_64 -enable-kvm -cpu host -m 512 -smp 2 -nographic \
  -drive file=vm.qcow2,if=virtio,format=qcow2,discard=unmap,detect-zeroes=unmap \
  -drive file=seed.img,if=virtio,format=raw,readonly=on \
  -nic user,model=virtio                 # prints GATE MARKER, then powers off
qemu-img convert -f qcow2 -O raw vm.qcow2 guest.raw && sha256sum guest.raw
./swarmblk checkpoint vm.qcow2 2>&1 | tee checkpoint.log
L=$(grep -o '0x[0-9a-f]\{40\}/[0-9a-f]\{64\}' checkpoint.log | head -1)
./swarmblk diff $S0 $L | wc -l
ssh test@192.168.1.225 mkdir -p swarmblk-gate && scp swarmblk test@192.168.1.225:swarmblk-gate/
```

On B (here run from A over SSH):

```sh
cd ~/swarmblk-gate
SWARMBLK_HOME=$PWD/home-b ./swarmblk export <lineage> restored.raw   # reports the sha256
```

Through node B from A:

```sh
ssh -f -N -o ExitOnForwardFailure=yes -L 1643:127.0.0.1:1633 test@192.168.1.225
SWARMBLK_HOME=$G/home-via-b ./swarmblk restore -bee http://127.0.0.1:1643 $L vm-b.qcow2
qemu-img convert -f qcow2 -O raw vm-b.qcow2 restored-via-b.raw && sha256sum restored-via-b.raw
pkill -f '[L] 1643:127.0.0.1:1633'      # closes the tunnel
```

The lineage key stays in `home-a/keys` on A; B gets neither the key nor the batch.
